# Мои пары · АПОб-22-

Личное расписание МГТУ с оформлением в стиле Apple. Работает на GitHub Pages без локального сервера, на Mac и телефоне.

Текущая пара показана крупной зелёной карточкой, следующая — светло-оранжевой. На перемене следующая карточка становится крупной. Время — Магнитогорск (UTC+5). Светлая и тёмная темы, ручное переключение недели, сохранение последнего расписания в браузере.

## Публикация

1. Создайте **публичный** репозиторий `my-timetable` на GitHub с основной веткой `main`.
2. Загрузите **содержимое этой папки**, включая скрытую папку `.github`. В корне репозитория должны находиться `site`, `scripts` и `.github`.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. Откройте **Actions → Update timetable and publish → Run workflow** и выберите `main`.
5. После успешного запуска ссылка появится в **Settings → Pages** и в результате задания `deploy`.

Не загружайте ZIP как один файл: GitHub его не распаковывает. Не публикуйте только `index.html`: нужны данные и задача обновления.

## Обновления

GitHub Actions получает страницу https://timetable.magtu.ru/АПОб-22- в 17-ю и 47-ю минуту каждого часа, разбирает обе недели, проверяет структуру и публикует JSON вместе с интерфейсом. Обновлённый снимок сохраняется в репозитории. В браузере кнопка «Проверить обновления» перечитывает опубликованный снимок, а не запускает обращение к МГТУ.

Если источник недоступен или изменил разметку, задача завершается ошибкой, предыдущий опубликованный сайт остаётся доступен. Если данные старше 90 минут, интерфейс показывает предупреждение. Неудачную задачу можно повторить через Actions.

Запуски GitHub по расписанию могут задерживаться; точный интервал в 30 минут не гарантируется. В публичных репозиториях GitHub может отключать запуски по расписанию после 60 дней без активности. Проверьте состояние Actions, если дата обновления устарела.

Исходники, снимки расписания и сайт публичны. Секреты, пароли и личные заметки сюда добавлять не нужно. Используются стандартные бесплатные Linux runners; платные сервисы и отдельный домен не нужны.

## Локальная проверка

```sh
python3 scripts/update_schedule.py
python3 -m http.server 8080 --directory site --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080. Для обновления требуется интернет. Сайт вуза предупреждает о возможных неточностях; сверяйтесь с официальным источником.
